# 다단 퍼즐 확장 검토

상태: 설계 제안. 이번 GitHub Pages 배포에는 현재 2D 규칙을 유지한다.

## 가능 여부와 추천
현재 순수 모델과 화면 표현이 분리되어 있어 다단 확장이 가능하다. 첫 확장은 **같은 위치에 2~3층을 쌓고 맨 위의 패만 선택하는 방식**을 추천한다. 기존 사천성의 '최대 두 번 꺾어 연결' 규칙을 유지하면서 아래 패를 드러내는 순서가 추가 전략이 된다.

- 각 위치는 아래→위 순서의 패 배열을 가진다. 맨 위 패만 선택/힌트 대상으로 삼는다.
- 연결 판정은 맨 위 패의 높이와 무관하게 평면 격자에서 수행한다. 즉, 길 중간에 한 장이라도 남은 위치는 통과할 수 없다. 외곽 통로는 유지한다.
- 한 쌍 제거 시 두 위치의 최상단 패만 제거하고, 아래 패는 제자리에 드러난다. 낙하나 중력 이동은 넣지 않는다.
- 잔여 패 수는 모든 층의 합이며, 전체 층이 비어야 클리어한다.
- 높이는 작은 측면 오프셋과 층수 배지로 표시한다. 가려진 패는 탭을 받지 않는다. 연결선은 별도 상위 레이어에 표시한다.
- 모바일은 최대 2층부터 시작하고, 기존 패 크기·버튼·캐릭터 안전 여백을 보장한다.

## 대안 비교
| 방식 | 규칙 변경 | 적합성 |
| --- | --- | --- |
| 깊이감만 있는 2.5D 표현 | 없음 | 외형 개선만 필요할 때 |
| 최상단 선택 + 기존 연결 규칙 | 중간 | 현재 게임에 자연스럽게 전략 추가; 추천 |
| 마작 솔리테어식 다층 | 큼 | 위가 비고 좌/우 한쪽이 열린 패만 선택; 사천성 연결선 규칙과는 별도 모드로 설계 |

## 필요한 구현
1. Board를 스택 구조로 확장하고 기존 2D 보드를 깊이 1로 취급한다.
2. 최상단 투영을 경로 탐색에 전달한다. 선택, 힌트, 제거, 전체 잔여량을 Game에서만 변경한다.
3. 생성 시 모든 층을 끝까지 제거할 수 있는 해답 순서를 보존한다. 층별 짝수 개수만으로는 전체 해법을 보장할 수 없다.
4. 섞기는 전체 남은 스택의 해법을 다시 구성하고, 무한 재시도 없이 제한 횟수와 검증된 복구 배열을 둔다.
5. 층수/오프셋/예상 가림 범위를 데이터로 정의하고, 타일·경로·캐릭터 영역의 겹침을 검사한다.
6. 점수와 기록을 classic/stacked 모드별로 분리하고 저장 스키마를 호환 이관한다.

## 하네스 게이트
- 덮인 패 선택 금지, 맨 위 패만 제거, 아래 패 공개, 중간 스택 장애물 및 외곽 경로 검사.
- 전체 층에 대한 seeded 해답 재생, 부분 제거 후 섞기, 막힘 복구, 마지막 층 클리어·중복 점수 방지.
- 2층/3층과 각 높이의 실제 클릭·터치, 가려진 패 입력 차단, 선택 테두리·연결선·캐릭터 패딩 확인.
- 기존 classic 테스트 회귀, 저장 마이그레이션, 모드별 기록 분리.
- 기존 순서대로 모델 → verify → E2E → 스크린샷 확인 → 문서/QA 기록 후 배포.

첫 구현 범위 제안: 기존 클래식 모드를 유지하고 '레이어 모드' 2층, 5개 스테이지를 추가. 3층과 마작식 규칙은 그 결과를 확인한 뒤 확장한다.
